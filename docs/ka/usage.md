# გამოყენება

## მართვის პანელი (რეკომენდებულია)

Plugins → DevBridge → **მართვის პანელი** (ასევე ღილაკი ხელსაწყოთა ზოლზე). ხუთი ჩანართი, ზემოთ —
ენის გადამრთველი (English / ქართული):

- **როგორ გამოვიყენო** — ნაბიჯ-ნაბიჯ ინსტრუქცია (პირველი ჩანართი).
- **VS Code** — ჰოსტი/პორტი, *დებაგ ხიდის გაშვება / გაჩერება*, სტატუსი.
- **PyCharm** — ჰოსტი/პორტი, *ავტო-კონფიგურაცია და გაშვება*, *გაჩერება*, ხელით ინსტრუქცია.
- **დანამატის მომზადება** — ჯერ აირჩიეთ, რა გინდათ: *არსებული დანამატის გაუმჯობესება* (სია ყველა QGIS პროფილს, QGIS 3-სა და 4-ს, მოიცავს), *ახალი დანამატის დაწყება* (ჩაწერეთ პატარა ლათინური სახელი; DevBridge ჩაწერს პატარა მუშა საწყის დანამატს თქვენი პროფილის plugins საქაღალდეში) ან *ნებისმიერი საქაღალდე*. მერე
  დააჭირეთ *დებაგისთვის მომზადებას*: შეიქმნება `.venv`, დაინსტალირდება `debugpy`, ჩაიწერება
  `.vscode/launch.json`. პროგრესი და pip-ის გამოტანა ლოგშია. *საქაღალდის გახსნა* / *გახსნა VS Code-ში*
  სახელის მიხედვით მუშაობს.
- **დესკტოპ ხელსაწყო** — *დესკტოპ ხელსაწყოს გაშვება* ხსნის დამოუკიდებელ ფანჯარას (იგივე ოპერაციები,
  QGIS-ის გაშვება არ სჭირდება, და შეუძლია DevBridge-ის დაყენება/ჩართვა თქვენს პროფილში);
  *ხელსაწყოს საქაღალდის გახსნა* მის საქაღალდეს ხსნის. მანქანაზე Tk-იანი Python უნდა იყოს (python.org-ის
  ინსტალატორებს აქვთ).

ერთ QGIS სესიაში მხოლოდ ერთი დებაგერია შესაძლებელი: VS Code (debugpy) ან PyCharm (pydevd) — გადასართავად გადატვირთეთ QGIS.

## QGIS-ის გაშვება უკვე მოქმედი ხიდით

`devbridge setup` ასევე წერს `.devbridge.json`-ს (ჰოსტი/პორტი/დანამატის სახელი) და მეორე VS Code launch
კონფიგურაციას, **"PyQGIS: Launch QGIS + attach"**. F5-ის დაჭერა ამ კონფიგურაციით უშვებს
`devbridge launch --wait-ready`-ს, რომელიც QGIS-ს `qgis --code`-ით უშვებს, ელოდება ხიდის მზადყოფნას და
მხოლოდ მერე აძლევს VS Code-ს დაკავშირების უფლებას — წინასწარ ხელით "დებაგ ხიდის გაშვება" აღარ სჭირდება.
ტერმინალიდან: `devbridge launch --wait-ready`; დესკტოპ ხელსაწყოში იგივეა ღილაკი **"QGIS-ის გაშვება (დებაგით)"**.
დადასტურებულია რეალურ QGIS 3.44.5-ზე (სტანდარტული ინსტალაცია და OSGeo4W).

პარამეტრები (ენა, პორტები) ინახება ერთ ფაილში, რომელსაც პანელი, დესკტოპ ხელსაწყო და
`devbridge` ბრძანება ინაწილებენ. მისი მდებარეობა *დესკტოპ ხელსაწყოს* ჩანართზე ჩანს.

## დებაგ სესიის დაწყება

1. QGIS-ში: **Plugins → DevBridge → დებაგ ხიდის გაშვება (VS Code)**.
   Message bar დაადასტურებს, რომ ხიდი უსმენს (ნაგულისხმევად
   `localhost:5678`).
2. VS Code-ში გახსენით პროექტი, რომელიც setup ინსტრუმენტმა
   დააკონფიგურირა, გადადით **Run and Debug**-ზე, აირჩიეთ **"PyQGIS:
   Attach to running QGIS"** და დააჭირეთ Start-ს.
3. დასვით breakpoint-ები თქვენს plugin-ის კოდში ან სკრიპტში; გაუშვით
   შესაბამისი მოქმედება QGIS-დან (მაგ. plugin-ის action ან სკრიპტი
   Python კონსოლიდან) — შესრულება გაჩერდება breakpoint-ზე.

## ცნობილი შეზღუდვა: ხიდის გაჩერება

`debugpy`-ს არ გააჩნია საჯარო API "listening socket"-ის დასახურად.
**დებაგ ხიდის გაჩერება** plugin-ის მენიუში მხოლოდ UI-ის მდგომარეობას
ანახლებს (რომ არასწორად არ გამოგიჩნდეთ "უკვე გაშვებულია") — თავად
socket ღია რჩება, სანამ QGIS არ გადაიტვირთება. ეს განზრახ არის
დოკუმენტირებული და არა დამალული, რომ სესიის შუაში არ გაგაკვირვოთ.

## PyCharm

PyCharm ვერ დაუკავშირდება იმავე `debugpy` ხიდს (განსხვავებული
პროტოკოლი), მაგრამ plugin ახლა ავტომატიზირებს მომზადებას:

1. PyCharm-ში: **Run → Edit Configurations → + → Python Debug Server**
   და გაუშვით (ჩაინიშნეთ host/port, ნაგულისხმევად `localhost:12345`).
2. QGIS-ში: **Plugins → DevBridge → PyCharm ხიდის ავტო-კონფიგურაცია და
   გაშვება**. ეს იპოვის თქვენს დაინსტალირებულ PyCharm build-ს (მისი
   `build.txt`-ის მეშვეობით), მოძებნის და დააინსტალირებს ზუსტად
   შესაბამის `pydevd-pycharm` ვერსიას PyPI-დან QGIS-ის ინტერპრეტატორში
   და დაუკავშირდება — ვერსიის ხელით ძებნის გარეშე.
3. ამ build-თან შესაბამისი, ხელახლა გამოსაყენებელი
   `pydevd_pycharm.settrace(...)` სკრიპტიც ინახება თქვენი QGIS
   პროფილის `devbridge/` საქაღალდეში — მოგვიანებით plugin-ის საკუთარ
   debug entry point-ში ჩასასმელად.

გაითვალისწინეთ, რომ კავშირის მიმართულება საპირისპიროა VS Code
ხიდისგან: PyCharm-ის "Python Debug Server" არის *მსმენელი*, QGIS კი
კლიენტია, რომელიც გარეთ უკავშირდება — ამიტომ ჯერ გაუშვით PyCharm-ის
run კონფიგურაცია, თორემ დაინახავთ შეტყობინებას "ვერ დაუკავშირდა".

თუ ავტომატურმა ძებნამ თქვენი PyCharm ვერ ჰპოვა (portable/unzipped
build, არასტანდარტული ინსტალაციის ადგილი, ან ქსელის არარსებობა
შესაბამისი `pydevd-pycharm` ვერსიის მოსაძებნად), გამოიყენეთ
**Plugins → DevBridge → ხელით PyCharm ინსტრუქცია...**, რომელიც
მიმართავს `.pycharm-debug/README.ka.md`-ს (`devbridge setup`-ის მიერ
გენერირებული) სრულად ხელით შესასრულებელი ნაბიჯებით.

## პორტის შეცვლა

```bash
devbridge setup --project-dir . --port 5679
```

ან ხელით შეასწორეთ `.vscode/launch.json` და plugin-ის **ხიდის
პარამეტრები...** დიალოგი შესაბამისობაში.
