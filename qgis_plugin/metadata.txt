about=DevBridge starts a debugpy server inside a running QGIS session so Visual Studio Code can attach and set breakpoints in plugin code or console scripts, without restarting QGIS; for PyCharm it detects your build, installs the matching pydevd-pycharm and connects. The Control Panel (Plugins > DevBridge) does everything with buttons, in English or Georgian: start/stop the bridges, pick one of your plugins and prepare it (a .venv that can import qgis, debugpy, VS Code launch configuration), open it in the file manager or VS Code. The same operations are also available as a separate desktop program bundled in the plugin's tool folder (launch it or open its folder from the panel); both share one settings file. Requires no extra Python packages except debugpy, which the preparation step installs.
changelog=0.2.12 - Bundled desktop tool (tool/devbridge) updated: 'devbridge launch' (VS Code's F5 "Launch QGIS + attach", the desktop tool's "Launch QGIS (debug)") no longer opens a redundant second QGIS when one with the bridge already listening is still open - it reuses it instead ('--force-new' to opt out). No change to the plugin's own code.
    0.2.11 - Bundled desktop tool (tool/devbridge) updated: new 'devbridge doctor --fix' retries what's safe automatically (plugin install/enable, debugpy, rerunning setup) and re-checks; a "Fix what's safe" button was added next to "Run diagnostics". No change to the plugin's own code.
    0.2.10 - Bundled desktop tool (tool/devbridge) updated: 'devbridge setup' now also writes PyCharm's "Python Debug Server" run configuration (.idea/runConfigurations/), the last fully-manual PyCharm step. No change to the plugin's own code.
    0.2.9 - Control Panel tabs now follow the order you actually use them in: "Prepare a plugin" moved before "VS Code" (used to come after PyCharm, contradicting the guide's own numbered steps). "How to use" now opens with a one-line tab roadmap.
    0.2.8 - Bundled desktop tool (tool/devbridge) updated: new 'devbridge new-script' command scaffolds a starter standalone PyQGIS script ready for headless debugging. No change to the plugin's own code.
    0.2.7 - Bundled desktop tool (tool/devbridge) updated: 'devbridge setup' now also writes a "PyQGIS: Debug current file (no QGIS)" VS Code launch config, for debugging a standalone script (QgsApplication, no running QGIS) directly. No change to the plugin's own code.
    0.2.6 - Bundled desktop tool (tool/devbridge) updated: warns when --host isn't local (debugpy/pydevd have no authentication of their own), and 'devbridge setup' now keeps .venv/__pycache__/.pycharm-debug out of git via .gitignore. No change to the plugin's own code.
    0.2.5 - Bundled desktop tool (tool/devbridge) updated: 'devbridge link-plugin' and 'devbridge uninstall' commands, automatic port-conflict handling in 'setup'/'launch', and an automated GitHub Release workflow for this repo. No change to the plugin's own code.
    0.2.4 - Bundled desktop tool (tool/devbridge) updated: 'devbridge doctor' (checks QGIS/debugpy/plugin/port/.vscode end to end) and a QGIS-installation picker for machines with several QGIS installs side by side. No change to the plugin's own code.
    0.2.3 - Built-in "Reload plugin" picker at the top of the Control Panel (visible on every tab): pick a plugin already enabled in this QGIS session and reload its code (qgis.utils.reloadPlugin) without a QGIS restart or the separate Plugin Reloader plugin.
    0.2.2 - Critical fix: the VS Code debug bridge never told debugpy which Python to use, so debugpy.listen() tried to launch its adapter through the QGIS program itself and failed after ~20-30s with "timed out waiting for adapter to connect" - confirmed with a real QGIS 3.44.5, every time. debugpy is now configured with the interpreter QGIS embeds before listen(); also treats a second listen() (plugin reload) as already-running instead of raising.
    0.2.1 - PyCharm: pydevd-pycharm is now installed into DevBridge's own folder with QGIS's real Python (it used to call the QGIS program itself), in a background thread with a live log; refuses to connect unless PyCharm is listening (a failed connect could crash QGIS); one debugger per QGIS session (VS Code or PyCharm) with a clear message. New "How to use" tab with step-by-step instructions (EN/KA), also in the desktop tool. "Prepare a plugin" now starts with a choice: improve an existing plugin (list over every QGIS profile, nothing pre-selected), start a NEW plugin (writes working starter files) or any folder.
    0.2.0 - Control Panel with tabs for VS Code, PyCharm, plugin preparation and the desktop tool; language switch EN/KA; standalone desktop tool bundled in the plugin (tool/), launchable from the panel; shared settings file; universal build for QGIS 3.40+ (Qt5) and QGIS 4 (Qt6).
    0.1.0 - First version: debugpy bridge menu and PyCharm auto-configuration.
